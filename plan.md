# План: Polar Workspace — персональный Claude web workspace

## Цель, границы и способ работы

Преобразовать текущий UI и начатый backend в полноценный **self-hosted веб-продукт** для одного владельца: на компьютере это широкая рабочая область, на телефоне — отдельная app-like версия с такой же доступностью функций, как в мобильном Claude, но реализованная как responsive web/PWA, а не native-приложение. Внутри — проекты, база знаний, история и поиск чатов, вложения, память, web search, создание файлов/artifacts и полноценная работа Claude Code с репозиторием.

Пользователь прямо запретил Anthropic API и SDK: приложение **не использует `@anthropic-ai/sdk`, Agent SDK, Console API key, API proxy или скрытую интеграцию Claude.ai**. Рабочий путь — неизменённая официальная программа Claude Code CLI, которую запускает self-hosted сервер в отдельном контейнере от имени владельца. Пользователь сам проходит штатный login flow внутри CLI на своём сервере; весь login/refresh/logout выполняет бинарник Claude Code. Веб-приложение не читает, не принимает, не логирует и не пересылает Claude OAuth tokens, cookies или credential-файлы. Запросы и лимиты принадлежат подписке пользователя, а не приложению. Перед каждым запросом по умолчанию действует ручное явное действие пользователя; фоновые вызовы не запускаются автоматически.

Использовать CLI в рамках официально описанного Anthropic сценария: бинарник не изменяется, владелец аутентифицируется в самом бинарнике, его использование не перепродаётся и не оплачивается приложением. Основываться на текущих CLI-возможностях `claude -p`, `--output-format stream-json`, `--session-id`/`--resume` и login flow; перед использованием проверять наличие CLI, а ошибки/неактивную авторизацию показывать честно. Ссылки на [официальные правила Anthropic](https://docs.anthropic.com/en/docs/claude-code/legal-and-compliance), [headless режим](https://docs.anthropic.com/en/docs/claude-code/headless) и [вход](https://docs.anthropic.com/en/docs/claude-code/authentication) зафиксированы в `research/`.

Не заявлять, что это официальный Claude-клиент Anthropic, что данные синхронизируются с Claude.ai или что локальная история/лимиты аккаунта являются официальной history/usage страницей: без API это отдельное локальное рабочее пространство. Не копировать закрытую реализацию, товарный знак или логотип Anthropic. Командные функции Team/Enterprise и синхронизация приватной истории Claude.ai не входят в личный self-hosted профиль. Реализовать локальные аналоги личного чата, проектов, базы знаний, памяти, artifacts и истории.

## Архитектура

- **Web client:** сохранить Vite + React + TypeScript, Polar визуальный язык и desktop workspace. Интегрировать его с реальными owner-authenticated API и SQLite вместо mock fixtures. Для телефона сделать отдельный responsive режим: компактный верхний header; нативный по ощущению одноколоночный поток; нижнюю навигацию; выдвижные sheets для проектов/файлов/контекста; удобную composer-панель, safe-area inset и touch actions. Все разделы доступны на мобильном, а не только скрыты ради адаптации. Обеспечить installable PWA и безопасное кеширование только публичного app shell, без приватных чатов и файлов.
- **Backend:** текущий Node 22/Express runtime — same-origin сервер приложения; SQLite WAL — канонический индекс пользователей, проектов, чатов, сообщений, памяти, вложений, артефактов и событий. Server-Sent Events используются для CLI token stream и состояния команды; WebSocket с owner session — для терминала и интерактивного login/CLI TTY. Клиент не обращается к внутренним или абсолютным адресам.
- **Claude runtime:** helper запускает реальный официальный `claude` бинарник с закреплённой командой, аргументами из allowlist, workspace cwd и ограниченным набором окружения; shell string interpolation запрещён. Для чата использовать поддерживаемый non-interactive CLI со stream-json, сохранять и восстанавливать связку локального chat ID ↔ официального CLI session ID. Для code-agent обеспечить команду/терминал, остановку процесса, структурированные tool events, ошибки login/model/limits и approvals до опасных изменений. Не патчить бинарник и не реализовывать свой протокол OAuth. CLI auth directory хранить отдельным персистентным Docker volume с правами владельца, не доступным через file API и downloads.
- **Модель и расходы:** приложение не поставляет ключей и не инициирует реальных запросов автоматически. Пользовательские запросы запускают CLI только после действия пользователя и расходуют его плановые лимиты. Не показывать выдуманный token/cost counter; показывать только информацию, которую CLI реально выдал и документация CLI разрешает показать, включая отдельные значения входных и выходных токенов в чате.
- **Projects / chats / files:** CRUD проектов и инструкций, отдельные чаты проекта, история и поиск, локальная memory/knowledge, перемещение/архивация, local attachments и создаваемые пользователем артефакты. CLI получает контекст из активного проекта и разрешённых вложений. Веб-поиск использовать только если установленный CLI предоставляет для текущей настройки соответствующие официальные инструменты; иначе переключатель показывает, что функция недоступна.
- **Workspace tools:** файлы читаются, создаются и сохраняются только в каталоге выбранного проекта. Все пути канонизируются; symlink escape, traversal, секреты и данные другого проекта закрыты. Терминал использует PTY с cwd выбранного workspace; Git — фактические status/diff/stage/unstage/commit, ветки и подтверждаемые user actions. Не скрывать удаление файлов, commit/push или запуск команд.
- **Self-hosted installation:** Docker Compose включает non-root app container, Caddy reverse proxy с HTTPS, `.env.example`, health check, persistent `/data`, `/workspaces` и изолированный `/claude-config` volume. Не монтировать root FS или Docker socket. Подготовить Ubuntu install/update/preflight и backup/restore scripts и полный README. В этой среде — только development preview и Git checkpoint; сайт не публиковать.
- **Бесплатный хостинг и регион:** setup script настраивает уже созданный Linux host, но не создаёт cloud account/VM/domain; managed free web instances с ephemeral storage и низкой памятью непригодны для постоянного SQLite/workspaces/CLI login. Always Free VM может быть кандидатом только если ресурс реально выдан владельцу; её доступность/верификация не гарантируются. Официальная политика Anthropic разрешает Claude Code только в перечисленных регионах и запрещает использование физически находящимся в неподдерживаемых регионах независимо от расположения сервера; не строить proxy/tunnel/foreign-host workaround. См. `docs/FREE_HOSTING.md`.
- **GitHub:** пользователь указал существующий `evgenmay1978-del/claude-code-workspace` (сейчас public) как целевой репозиторий для self-hosted исходников. В рамках этого handoff обновлять его через заранее авторизованный GitHub CLI, сохранять его `main` историю и удалять только устаревшие файлы приложения. Это отдельная синхронизация с существующим репозиторием, а не смена активного canonical repository WebDev. Текущий WebDev-проект остаётся на Manus-managed repository; production publish не выполнять.

## Структура проекта

- `src/`: React SPA, desktop workspace, mobile navigation/screens, auth/onboarding, чат/composer/uploads, settings, PWA shell; `src/lib/` — typed HTTP/SSE/WebSocket client и domain state.
- `server/index.ts`, `server/app.ts`: production/development entry, HTTP server, health check и UI serving. `server/auth/` — password owner session, CSRF, rate limit и сессии.
- `server/db.ts` и `server/db/`: SQLite WAL, migrations и queries для users/projects/conversations/messages/attachments/memory/artifacts.
- `server/routes/`: auth, projects, sessions, messages, search, attachments, artifacts, files, git, terminal, Claude CLI.
- `server/claude/`: CLI discovery, command argument builder, child-process streaming, PTY/login flow, session resume, output parser, cancel/errors; никакого Anthropic API/SDK или token parsing.
- `server/workspaces/`, `server/terminal/`, `server/git/`, `server/security/`: workspace sandbox/path checks, PTY lifecycle, Git operations и security controls.
- `public/`: favicon, route manifest, PWA manifest/icons. `scripts/`: setup/preflight, backup/restore, CLI diagnostics.
- `Dockerfile`, `docker-compose.yml`, `Caddyfile`, `.env.example`, `README.md`: переносимая установка на VPS и upgrade.

## Дизайн-система

- **Design Movement:** северная полярная консоль — спокойная инженерная эстетика редактора кода, без киберпанк-декора и без копирования визуальных материалов Claude.
- **Core Principles:** понятный проект и текущая беседа; плотная, но читаемая desktop workspace; полноценный мобильный поток с лёгким доступом к каждому разделу; прозрачная граница между локальными данными приложения и официальным CLI.
- **Color Philosophy:** сине-графитовый фон `#071827` создаёт глубину; холодные контуры отделяют панели; текст остаётся контрастным; коралловый `#FF8066` обозначает активное действие; зелёный/янтарный сообщают о реальном статусе процесса.
- **Layout Paradigm:** на desktop асимметричная IDE-область — узкий rail, список проектов/чатов, центр беседы/файла и context panel. На phone — отдельная одноколоночная модель: чат занимает экран, нижние вкладки открывают самостоятельные разделы, детали появляются в sheets, а Composer закреплён над safe-area.
- **Signature Elements:** полярная искра внутри проектных скобок; орбита реального статуса агента; ледяные контурные разделители и компактные моноширинные метки.
- **Interaction Philosophy:** явное действие пользователя запускает Claude; видны старт, stream, stop, завершение и ошибка; до записи/удаления/опасной команды показывается конкретный scope; on-phone кнопки рассчитаны на touch и доступны одной рукой.
- **Animation:** 120–180 мс для панелей, вкладок и статуса; плавный поток текста и раскрытие sheets; никаких непрерывных анимаций; соблюдать `prefers-reduced-motion`.
- **Typography System:** Golos Text для интерфейса и заголовков; системный monospace для кода, путей, команд, diff и статуса процесса; desktop: заголовки 22/16 px и основной текст 13–14 px; mobile: комфортный читаемый текст и кликабельные области не меньше 44 px.
- **Brand Essence:** личная web-рабочая среда для разработчика, соединяющая диалоги, проекты и локальный Claude Code на собственном сервере; спокойная, точная, пользовательская.
- **Brand Voice:** прямой текст и фактические статусы, без обещаний обхода регионов и без имитации Anthropic-официального продукта. Примеры: «Код — в работе. Контекст — под контролем.»; «Claude Code запустится только по вашему запросу.»
- **Wordmark & Logo:** собственный знак Polar — угловые скобки проекта с коралловой северной искрой; wordmark `POLAR WORKSPACE`. Упоминание «работает с Claude Code» — только как точное plain-text описание совместимости.
- **Signature Brand Color:** полярный коралл `#FF8066`.
