# Бесплатный хостинг и домен: проверенные ограничения

**Проверено: 11 октября 2026 года.** Это приложение запускает настоящий Claude Code CLI, node-pty, потоковый SSE и хранит SQLite, рабочие каталоги и CLI-конфигурацию. Для пригодного постоянно работающего размещения нужны Linux/Docker, постоянный writable storage, заметно больше ресурсов, чем у минимальных бесплатных web-инстансов, и корректно настроенный HTTPS.

## Короткий вывод

Среди проверенных бесплатных managed web-планов я не нашёл варианта, который одновременно даёт стабильный долгоживущий процесс, постоянное файловое хранилище для SQLite/workspaces/CLI login и подходящие ресурсы для CLI/PTY. Бесплатный план может подойти для статической демонстрации интерфейса, но это **не** полноценное размещение данного сервиса.

Oracle Cloud публикует Always Free VM-ресурсы, которые технически могут быть кандидатом для Docker-инсталляции: до 2 OCPU, 12 GB RAM и общий лимит 200 GB block volume. Это не означает гарантированную выдачу VM: Oracle ограничивает capacity, требует настоящие контактные/платёжные данные и карту для проверки личности, допускает приостановку заброшенного аккаунта и может reclaim-ить idle compute. Аккаунт/VM пользователь создаёт сам; скрипт проекта не должен обходить карточную проверку или автоматически регистрировать аккаунт.

DuckDNS даёт бесплатный динамический DNS-поддомен вида `name.duckdns.org`; это **не** бесплатная регистрация собственного домена верхнего уровня. Для автоматического обновления IP нужен аккаунт и его токен. Сервер всё равно должен существовать и быть доступен из интернета.

## Почему бесплатные web-тарифы здесь не подходят

- **Render Free:** сервис засыпает после периода без входящего трафика; локальная файловая система теряется при restart/redeploy/sleep; persistent disk для Free web service недоступен; опубликованные лимиты — 512 MB RAM и 0.1 CPU. Поэтому SQLite, workspace-файлы и CLI login нельзя надёжно хранить на самом бесплатном инстансе. Render сам пишет, что Free instances не предназначены для production.
- **Railway Free:** официальная тарифная таблица показывает `$1/month` included usage, предел `0.5 GB RAM` на сервис и volume, а custom domains для Free отсутствуют. Это ограниченный кредит, а не гарантированный круглосуточный хостинг требуемой мощности.
- **Cloudflare Quick Tunnel:** создаёт временный случайный `trycloudflare.com` адрес без собственного домена; URL перестаёт работать с остановкой процесса, гарантий uptime нет, hostname меняется, а **SSE не поддерживается**. Поскольку чат этого приложения работает через SSE, Quick Tunnel не обеспечивает полный чат даже как долгосрочный бесплатный endpoint.

Установщик `scripts/setup.sh` работает **на уже созданном Linux-хосте**: проверяет Docker Engine/Compose, принимает готовое публичное доменное имя, записывает локальный `.env`, собирает контейнеры и запускает Caddy. Он не создаёт облачный аккаунт/VM, не покупает/регистрирует домен, не устанавливает Docker, не меняет firewall/router и не подтверждает личность у провайдера. Поэтому он не является кнопкой «бесплатно создать интернет-хостинг из ничего».

## Важное ограничение Claude Code

Официальная [Supported Regions Policy Anthropic](https://www.anthropic.com/supported-countries) распространяется в том числе на Claude Code. Anthropic указывает, что пользоваться сервисом нельзя, находясь физически в неподдерживаемом регионе, даже если учётная запись или компания находится в поддерживаемой стране. Россия в опубликованном перечне поддерживаемых стран не указана. Перенос web-сервера в другую страну, домен, tunnel, proxy или попытка скрыть физическое местоположение не меняют это правило. Поэтому я не буду настраивать размещение, цель которого — обойти региональные ограничения или скрыть использование Claude Code.

Официальный CLI/self-host вариант из этого репозитория предназначен для владельца, который пользуется им из региона, поддерживаемого Anthropic. Никакой бесплатный тариф, домен или установочный скрипт не делает неподдерживаемый доступ разрешённым.

## Что можно сделать дальше

1. Если нужен **только просмотр интерфейса**, можно отдельно подготовить публичный UI-preview, но он не будет полноценным CLI workspace, не должен выдавать фиктивные ответы и не будет хранить реальные owner data.
2. Если нужен **реально бесплатный вариант для использования без Anthropic**, потребуется отдельная продуктовая опция с локальной моделью/локальным coding-agent runtime на собственном постоянно включённом компьютере или подходящем VM. Это другой provider и дополнительные зависимости; сейчас в проекте этого runtime нет, поэтому я не подключал его молча.
3. Если владелец будет использовать официальный CLI **из поддерживаемого Anthropic региона**, можно автоматизировать установку приложения на уже существующую VM, а для тестового DNS использовать DuckDNS-поддомен. Создание облачного аккаунта/VM и проверка, что бесплатная ёмкость выдана именно этому аккаунту, всё равно требуют действий владельца.
